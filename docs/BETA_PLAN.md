# Mystic Calculator Beta Plan

## 베타 목표

알파는 `신비갈피/하늘석/천장까지 남은 횟수`를 입력해서 천장 가능 여부, 비상런 기대값, 패키지 추천, 결과 캡쳐까지 확인하는 단일 흐름이다.

베타의 목표는 기능 수를 늘리는 것보다 다음 세 가지를 안정화하는 것이다.

1. 계산 결과를 믿을 수 있게 만든다.
2. 사용자가 자기 상황을 더 빠르게 입력하고 비교하게 만든다.
3. 공유/유입/피드백 루프를 만들어 다음 버전의 근거를 확보한다.

## 베타 핵심 업데이트

### 1. 계산 신뢰도 강화

현재 계산 결과는 잘 나오지만, 사용자가 왜 그런 결과가 나왔는지 검증하기 어렵다. 베타에서는 결과 화면에 계산 근거를 얇게 노출한다.

구현 항목:

- 결과 화면에 `계산 기준` 접이식 섹션 추가
- 신비 1뽑 비용, 5성 확률, 비밀상점 리롤 비용, 신비 메달 등장 확률 표시
- 초반 30뽑 할인 적용 여부와 절약 갈피 표시
- `패키지 추천은 기대값 기반 참고값`이라는 고지 유지 및 더 명확화

수용 기준:

- 사용자가 결과 화면에서 주요 상수를 확인할 수 있다.
- 접힌 상태에서는 기존 결과 화면의 밀도가 크게 늘어나지 않는다.
- 캡쳐 이미지에는 핵심 결론만 남고, 상세 근거는 제외하거나 선택 가능하다.

### 2. 입력 UX 개선

알파 입력값은 세 개뿐이라 단순하지만, 실제 사용자는 여러 상황을 빠르게 비교하고 싶어 한다.

구현 항목:

- 입력값 프리셋 버튼 추가
  - `천장 초기화`: 남은 횟수 200
  - `반천장 근처`: 남은 횟수 100
  - `막판`: 남은 횟수 30
- 최근 입력값 localStorage 저장
- `초기화` 버튼 추가
- 입력값 변경 후 결과 화면에서 바로 수정할 수 있는 `입력 수정` 버튼 추가

수용 기준:

- 새로고침 후 마지막 입력값이 복원된다.
- 사용자는 결과에서 처음 화면으로 돌아갔을 때 기존 입력값을 잃지 않는다.
- 모바일에서 프리셋 버튼이 줄바꿈되어도 입력 영역을 밀어내지 않는다.

### 3. 결과 공유 강화

현재 `html-to-image` 기반 결과 캡쳐가 있다. 베타에서는 공유되는 이미지와 링크의 품질을 올린다.

구현 항목:

- 캡쳐 전용 레이아웃 정리
- 캡쳐 이미지 하단에 서비스명/URL/계산 시각 표시
- Web Share API 지원 환경에서는 이미지 공유, 미지원 환경에서는 다운로드 유지
- URL 쿼리로 입력값 공유 지원
  - 예: `?pity=120&medals=3000&skystones=9000&discount=1`
- 공유 URL 진입 시 입력값 자동 복원 및 바로 결과 보기 옵션 검토

수용 기준:

- 공유 이미지만 봐도 천장 가능 여부와 부족 갈피가 즉시 보인다.
- 공유 링크를 열면 동일 입력값이 복원된다.
- 민감한 사용자 정보를 저장하거나 서버로 보내지 않는다.

### 4. 패키지 추천 데이터 신뢰성 개선

현재 패키지 데이터는 수동 데이터이며 `salePeriod`에 연도가 없다. 베타에서는 이 부분이 가장 큰 신뢰 리스크다.

구현 항목:

- 패키지 데이터에 `startsAt`, `endsAt` ISO 날짜 필드 추가
- `sourceLabel` 또는 `sourceUrl` 필드 추가
- 만료된 패키지는 추천에서 제외하고, 데이터 기준일 표시
- `추천 패키지 전부 구매 시` 대신 `표시된 추천 후보 합계`로 문구 조정
- 신비와 무관한 패키지는 기본 추천에서 제외하거나 낮은 우선순위로 격리

수용 기준:

- 현재 날짜 기준 만료 패키지가 추천에 섞이지 않는다.
- 사용자가 패키지 데이터 기준일을 확인할 수 있다.
- 신비 보충에 직접 도움이 없는 패키지는 상위 추천에 노출되지 않는다.

### 5. 알파 피드백 수집

베타부터는 감으로 개선하지 않도록 최소한의 피드백 채널을 만든다.

구현 항목:

- 결과 화면 하단에 짧은 피드백 링크 추가
- `계산이 맞았나요?` 단일 질문 형태의 외부 폼 또는 GitHub issue 링크 연결
- 익명 분석 도구 도입 여부 결정
  - 이벤트 후보: 계산 실행, 캡쳐 클릭, 패키지 추천 노출, 공유 링크 유입

수용 기준:

- 피드백 진입점이 결과 화면을 방해하지 않는다.
- 개인 입력값을 자동 수집하지 않는다.
- 다음 릴리즈에서 볼 수 있는 최소 데이터가 생긴다.

## 우선순위

### P0: 베타 필수

- 계산 기준 접이식 섹션
- localStorage 최근 입력값 저장
- 공유 URL 쿼리 지원
- 패키지 데이터 날짜 구조 개선
- index.html 메타/OG 태그 정리

### P1: 베타 품질 향상

- 프리셋 버튼
- 캡쳐 이미지 워터마크/계산 시각
- 피드백 링크
- 패키지 추천 문구 개선
- README 인코딩/문서 정리

### P2: 베타 이후 후보

- 성약뽑기 계산기
- 강화 확률 계산기
- PWA 설치 지원
- 다크/라이트 테마
- 서버 기반 패키지 데이터 업데이트

## 추천 릴리즈 범위

베타 1차는 다음 범위로 자르는 것이 좋다.

1. 입력값 저장과 공유 URL
2. 계산 기준 노출
3. 패키지 데이터 구조 개선
4. SEO/공유 메타 정리
5. 캡쳐 결과물 정리

이 범위는 기존 앱의 핵심 흐름을 유지하면서 신뢰도와 공유성을 동시에 올린다. 새 계산기를 추가하는 작업은 베타 1차 이후가 낫다.

## 구현 순서

1. `index.html` 메타 태그와 앱 제목 정리
2. 입력값 직렬화/역직렬화 유틸 추가
3. localStorage 저장 및 URL 쿼리 복원 연결
4. 결과 화면에 계산 기준 접이식 섹션 추가
5. 패키지 데이터 날짜 필드 마이그레이션
6. 캡쳐 전용 하단 정보 추가
7. 빌드, 모바일 확인, 공유 URL 수동 테스트

## 체크리스트

- `yarn lint`
- `yarn build`
- 모바일 360px, 390px, 430px 확인

- 입력값 비어있을 때 결과 확인
- 천장 0회, 1회, 200회 확인
- 할인 ON/OFF 비교
- 패키지 만료일 필터 확인
- 캡쳐 이미지 확인
- 공유 URL 복원 확인
